# UniPlan 本地前端

在本目录运行：

```bash
python3 main.py
```

浏览器打开 <http://127.0.0.1:8766/>。如需换端口，运行 `python3 main.py --port 8767`，并使用终端显示的地址。也可用 `python3 -m uniplan` 启动。只用 Python 标准库，无需安装依赖。

当前流程包含：

1. `uniplan/profile.py` 的 `prepare_student_profile()` 校验并标准化学生输入。
2. `uniplan/timetable_data.py` 的 `load_timetable_data()` 读取本地公开课表快照，返回逐次活动和班级概况。每个活动组附带活动类型和默认勾选建议：来源标记 IGN 和非教学活动（如答疑）默认不选。
3. `uniplan/arrangement.py` 的 `arrange_timetables()` 是编排模块入口，调用 `schedule.py` 提取完整班级选项，并通过回溯搜索为每个选定活动组选出一个班级。
   - `01-P1`、`01-P2` 等同一班级的分段会合并，保留全部教学日期。
   - 满员、实际时间冲突和换楼缓冲不足的组合会被排除；普通教学活动避开用户设置的时段，Assessment、Test、Quiz 则保留并标注例外日期。
   - 没有可行组合时，`find_conflict_core()` 找出互相冲突的最小活动组集合，并说明是时间重叠还是换楼缓冲不足，但不会放宽条件。
   - 搜索若超过上限会停止，不输出不完整的排序。
4. `uniplan/ranking.py` 计算每周空档 G、到校天数 D 和偏好时段外分钟数 O。
   - **候选短名单（主界面）**：`pareto_front()` 去掉被支配的组合，即在三项上都不比另一组合好的组合。实际课表中通常只剩 1–4 种，每种还按“哪几天到校”列出不同版本。
   - **规则排序**：前三种不同特征组合、同分方案数、可单独互换的班级，以及 ±25% 尺度敏感性检查。评分定义见 `RANKING_PLAN.md`。
5. `uniplan/preference.py` 与 `uniplan/study.py` 是可选的个人偏好学习：从可行方案中抽出 10 份课表，请学生做 16 次二选一，用其中 12 次拟合个人逻辑回归，留出 4 次检验。短名单只有 1–4 种时，页面会说明直接比较更快。
6. `uniplan/choice_model.py` 是群体取舍模型：把同意保存的“从短名单中选了哪一个”（以及二选一结果）合并起来，拟合条件 logit，估计同学们在空档、到校天数和时段之间如何取舍。

`uniplan/main.py` 的 `main()` 顺序调用这些函数；根目录的 `main.py` 启动 HTML 前端。公开课程名称索引用于搜索建议，不能证明该学期有对应课表。

## 数据获取

提交表单后，`uniplan/auto_fetch.py` 会自动检查所选课程：

1. 先复用最近 24 小时内的本地快照，再尝试本地抓取缓存。
2. 需要联网时，先检查课表网站的 `robots.txt`，并且只查询输入的课程代码。
3. 成功获取后保存带时间戳的 CSV，刷新目录，再继续运行主程序。查询期间页面显示进度。

目前目标网站的 `robots.txt` 禁止自动请求，默认服务不会绕过这条规则。

- **有本地旧缓存时**：页面用旧数据生成**试算**结果，在顶部标出数据日期和天数，并提示座位和时间可能已变化。
- **完全没有本地数据时**：页面说明实时查询受阻。
- **获得许可后**：如果你已获得进行这些有限查询的许可，可用 `python3 main.py --allow-robots-disallowed` 启动。这会启用实时查询，仍按 1 秒请求间隔和 24 小时缓存工作。当前原型不提供稳定官方 API 的保证。

## 页面流程

1. **输入**：添加课程，点选“周五全天”“10 点前”等常用限制（也可自定义），点“生成课表”。“更多设置”分四组，留空表示不限：

   | 分组 | 设置 | 作用 |
   | --- | --- | --- |
   | 每天 | 希望上课时间 | 计算“早晚课”时间，只影响排序 |
   | 每天 | 最多上课 N 小时、最长在校 N 小时 | 硬性限制（考核不受限） |
   | 每天 | 留出午饭时间 | 在指定时段内至少空出若干分钟（硬性） |
   | 每周 | 最多到校 N 天 | 每个教学周的线下到校天数上限（硬性） |
   | 路上 | 单程通勤 | 计算每周路上时间，显示在“时间”页 |
   | 路上 | 换楼至少留 | 不同教学楼之间的固定缓冲 |
   | 路上 | 按楼间距离算步行 | 按建筑之间的实际距离和所选步速（正常 / 较慢 / 行动不便）估算换楼时间 |
   | 选班 | 只要现场课 | 有现场班时不选线上班 |
   | 选班 | 避开余位少于 N 的班 | 减少报不上的风险；已固定的班不受影响 |

2. **结果**：设置区收起成一行，可随时“修改”。页面只列出值得考虑的方案，每个方案显示每周到校天数、空等时间、早晚课时间和缩略周课表；“我在意”开关可以即时筛选；同一方案若有不同的上课日组合，可在卡片上切换。宽屏时左边是方案列表、右边是详情；手机上上下排列，列表里不显示缩略图。点方案右上角的“对比”选两个方案，右侧并排显示两份周课表、三项指标的差值，以及哪几门活动的班不同。

   界面是平面的：没有圆角卡片和阴影，用细线分隔，按钮只有文字。支持深色模式（跟随系统，也可用右上角“深色 / 浅色”切换并记住）。

3. **方案详情**分五个标签：

   | 标签 | 内容 |
   | --- | --- |
   | 周课表 | 按真实日期逐周翻看（学期中默认打开本周，标出今天和当前时间，← → 键换周），换楼紧张时提醒。点某一天的表头，显示当天在各楼之间的路线图、每段空档和步行估算，以及学校地图链接 |
   | 学期 | 13 周到校热力图（每天线下几小时、哪天只有线上课、考核日描边，标出本周、今天和期中假，过去的日子变淡），以及考核、一次性实验等不在每周固定时间的课，三周内的标出“N 天后” |
   | 时间 | 每周时间账本（上课、空等、通勤）、典型一周每天的到校时间，以及 9:00–18:00 内 3 小时以上的整块空闲（便于安排打工或自习） |
   | 选课 | 按风险排出登记顺序，顶部显示进度。选课当天逐个点“报上了”或“满了”：标为满了时，保留已报上的班，排除这个班，再重新安排其余的；每一步都可以撤销 |
   | 和朋友 | 粘贴朋友分享的方案链接，查看哪些课同班、两人都在学校又都有空的午饭时段；可一键“尽量和朋友同班” |

   详情顶部在开学前两周到学期结束之间显示“下一节课”（时间、课程、教室）。右上角可以导出日历、复制分享链接、收藏（保存在本机浏览器，下次在首页直接打开）、打印，或点“就选这个”（随后跳到“选课”）。

4. **提示与修改**：如果去掉某个限制能明显改善结果，页面用一行提示，并可一键修改；限制没有代价时也会说明。排不出课表时，页面说明原因（时间冲突、每天或每周限制、选班条件、换楼时间，或某个活动的班都被标为已满），并给出只改一处就能排出的办法。对“每周最多到校”“每天最多上课”“每天最长在校”，先找能排出来的最小放宽（例如 1 天改为 4 天）；和完全取消效果一样时只显示这个较小的改动。所有一键修改都可以撤销。

5. **调整课程活动与班级**：可以勾选或取消活动组、固定某个班，或一键把 Lecture 改为看录播。“看全部班级”把一个活动的所有班画在周课表上：按余位着色、标出已满的班、在你避开时间里的班、会和当前方案其他课冲突的班，以及当前方案用的班；点一个班即固定它。

6. **分享**：网址会随设置自动更新，复制给别人即可打开同样的设置并自动生成。研究用的 16 组偏好比较只在网址加 `?study=1` 时显示。

## 各种情况怎么处理

| 阶段 | 情况 | UniPlan 的做法 |
| --- | --- | --- |
| 输入 | 课程代码打得快，名称来不及显示 | 添加后自动补查课程名称 |
| 输入 | “周五不来”“早上 10 点前不上课”等常见限制 | 一键预设，自动生成对应时段，不重复添加 |
| 输入 | 已经报上某个班，或想和朋友同一个 tutorial | 活动组旁的下拉框可“固定为”某个班；即使该班显示已满也可固定（你可能已占座），其余课程围绕它排 |
| 输入 | Lecture 打算看录播 | 一键取消全部 Lecture 组，不再占时间、不计到校天数（需确认课程允许） |
| 输入 | 不知道哪些活动组必须参加 | 教学组默认勾选；答疑等非教学组和来源标记 IGN 的组默认不选；结果标明“按你选择试算” |
| 数据 | 网站禁止自动抓取，本地缓存已过期 | 用旧数据试算，顶部显示数据日期和天数，并提示座位和时间可能已变化 |
| 数据 | 几门课的数据来自不同日期 | 按每门课最新的一份合并，列出各课日期，整体日期按最早的一份显示 |
| 数据 | 某门课完全没有本地数据 | 明确列出缺少的课程，并提示到学校官方课表核对 |
| 计算 | 4–5 门课组合过多 | 等价班级只搜索一次；冲突关系预先算成位集并提前剪枝；三项指标增量计算。5 门课共 2,430 万份课表约 4 秒算完（旧版 178 秒后报错）；超出上限时指出选项最多的活动组 |
| 没有方案 | 不知道为什么排不出 | 指出互相冲突的最小活动组集合及其时间，并在列表中标出“冲突” |
| 没有方案 | 不知道怎么改 | 逐项检查只改一处能否排出（去掉某个时段、换楼缓冲改为 0、不参加某组、取消某个固定班级），给出可行方案数和一键修改按钮；不会自动放宽 |
| 有方案 | 几千份课表看不过来 | 去掉被支配的方案后通常只剩 1–4 种，并排显示每周到校天数、空等时间、早晚课时间和缩略周课表 |
| 有方案 | 不想填 0–5 的数字权重 | 用“我在意：少到校 / 少空等 / 少早晚课”三个开关，方案列表即时更新 |
| 有方案 | 指标一样，但想要不同的上课日 | 每个方案可切换“上课日”版本，如周二三四 / 周二三五 |
| 有方案 | 自己的限制代价有多大 | 逐项显示：去掉某个限制后，最少到校天数、空档、时段外分钟各能降到多少，可一键试试 |
| 生活安排 | 要打工、每天不想上太久、要吃午饭、一周只想来两天 | “更多设置”里的每天和每周限制都是硬性约束；“时间”页列出可以打工或自习的整块空闲 |
| 生活安排 | 通勤远 | 填单程通勤时间后，“时间”页显示每周路上时间和总时间 |
| 无障碍 | 走得慢或行动不便 | 按楼间实际距离和所选步速估算换楼时间，并作为硬性约束 |
| 无障碍 | 想知道某天要走多少路 | 点周课表的星期，显示当天的楼间路线图、每段空档够不够走过去 |
| 比较 | 两个方案差在哪 | 选两个方案并排对比：周课表、三项指标差值、班级不同的活动 |
| 固定班级 | 不知道一个活动有哪些班、哪个还有座位 | “看全部班级”在周课表上显示所有班的时间、余位和冲突，点一下即固定 |
| 学期中 | 今天、这周、下一节课在哪 | 默认打开本周，标出今天和当前时间，详情顶部显示下一节课 |
| 学期中 | 期中假在哪 | 学期热力图在相隔超过一周的两个教学周之间标出“期中假” |
| 操作 | 改错了、标错了“满了” | 每次一键修改、标满、同班重排后都可撤销，恢复限制、固定、已报状态 |
| 限制太严 | 只想放宽一点，不想完全取消 | 对天数和时长限制给出能排出来的最小放宽 |
| 学期 | 想知道哪几周特别忙、考核在哪天 | “学期”页的热力图和重要日期 |
| 选课当天 | 报到一半某个班满了 | 在“选课”页点“满了”：保留已报上的班，自动重排其余的 |
| 朋友 | 想和朋友上同一个 tutorial | “和朋友”页对比两人方案，一键同班 |
| 朋友 | 想约朋友一起吃午饭 | 分享链接带上每周固定的上课时间，对比时列出两人都在学校又都有空的午饭时段 |
| 记录 | 下次还想看、发给别人、打印 | 收藏到本机、复制分享链接、打印 |
| 选课当天 | 推荐的班只剩 1 个座位，旁边同时间的班还剩 30 个 | 指标与上课日完全相同时，自动换成余位更多的班 |
| 选课当天 | 先抢哪个班 | 按余位和有没有同等替代排出登记顺序 |
| 选课当天 | 某个班满了怎么办 | 每门课列出单独替换的备选班级，以及替换后三项指标的确切变化 |
| 选课当天 | 两节课紧挨且在不同楼 | 显示换楼提醒：间隔分钟数、建筑之间的直线距离和粗略步行时间（仅估算） |
| 选定后 | 记到日历、发给自己 | 导出 `.ics`（悉尼时区，含夏令时）；选课清单可一键复制 |
| 研究 | 同一个人试了多组课程 | 同意保存后，所有记录共用一个参与码；撤回时一次删除全部 |

## 隐私

页面默认不保存任何内容。只有勾选同意后，以下内容才保存在本机 `data/private/profiles.sqlite3`：

- 档案；
- 比较答案（`choices` 表，含训练/检验划分）；
- 用时与采用记录（`outcomes` 表；采用短名单方案时含整个短名单的 G/D/O 与所选序号）。

第一次保存后，页面显示一个参与码；同一页面里之后保存的课程组合都归到这个参与码下。用它可以一次撤回全部记录。座位和时间可能变化，最终安排仍应在学校官方系统核对。

## 研究脚本

- `scripts/simulate_preference_learning.py`：用已知答案的模拟学生比较各种学习设置与基准。结论见 `RESEARCH_NOTES.md`。
- `scripts/evaluate_pilot.py`：按提案第 4 步评估已同意的试点数据，包括参与者平均的留出准确率、bootstrap 置信区间、与较强基准的配对差值，以及首次使用用时。
- `scripts/simulate_menu_choices.py`：在随机约束下用真实搜索生成短名单库，模拟不同规模的试点，检验群体模型的预测力和估计精度。
- `scripts/fit_population_model.py`：用真实试点数据拟合群体取舍模型，报告各项影响占比及其置信区间，以及留一参与者预测准确率。

## API

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/catalog` | 本地快照与课程名称索引 |
| `GET /api/suggest?q=` | 课程代码建议，不联网 |
| `POST /api/prepare` | 校验输入、获取数据、编排排序；带 `required_groups` 时同时返回比较题 `study` |
| `POST /api/study` | 提交 `{study_id, answers:[{pair_id, choice: left/right/tie}]}`，返回学习结果 |
| `POST /api/accept` | 记录“采用此方案”及用时（仅限已同意保存的档案）；`method: "shortlist"` 时附带 `menu`（各方案 G/D/O）、`chosen` 与 `axes` |
| `DELETE /api/profiles/<code>` | 撤回档案及其全部比较和用时记录 |
