# 打分排序（机器学习 A）结果

> **全部是合成数据和 AI 产出。** 80 个学生画像由 Claude 编写；训练标签由千问（qwen2.5:14b）扮演这些画像给出；核对答案由另一个模型 Claude（总控窗口）给出。没有任何真实学生或组员的数据。课表本身来自 2026 年第二学期真实的公开课表快照。

## 要解决的问题

排课程序给一个学生排出 10–20 份都不冲突的课表，`rank()` 要按「对这个学生最合适」排序，取前 3。
没有真实学生的偏好数据，所以做法是：让大模型扮演学生做二选一，当「老师」打标签；再训练一个只用标准库就能跑的小模型去学老师的判断。

## 1. 学生画像（`llm/rank/data/personas.json`）

- 80 个，10 类各 8 个：通勤远、打工、带孩子、夜猫子、实习、住得近、早起/晚上有事、运动队/社团、照顾家人/身体原因、其他（只要线下课、午饭、交换生等）。
- 每个画像是一句话，加上这句话对应的硬性条件和偏好（`llm/contracts.py` 的 Conditions 格式）。`cares` 按重要性排序，`cares[0]` 是最在意的一项。
- 最在意到校天数 28 个，空等 27 个，早晚课 25 个。有 14 个画像在意两项。
- 有硬性条件的画像：不能来的时段 34 个、每周最多天数 5 个、每天在校时长 4 个、午饭 4 个、每天上课时长 3 个、只要线下课 2 个。21 个有自己的方便时段（`preferred_hours`）。
- 每个画像都能排出至少 31 种不同的课表（中位数 634 种）。
- 训练和测试按画像划分：每类 2 个测试画像，共 20 个，打标签之前用固定种子定好，测试画像不进训练。试验用的 6 个画像固定放在训练集。
- 核对中发现 3 句话里的「课排得集中」「课别太分散」有两种读法（少来几天，或少空等），已在打正式标签之前改成「紧凑」「课和课之间别空太久」。

## 2. 课表特征（`llm/rank/features.py`，只用标准库）

13 项，都是每个教学周的平均值：到校天数、课间空等、早晚课（按学生自己的方便时段算，并分成早课和晚课）、最早上课、最晚下课、最长的一天、上课最多的一天、周五不用到校、换楼次数、只为一节课到校的天数、线上课比例。
前三项和排课程序原来的计算在 172 份课表上完全一致。

## 3. 老师标签

### 提示词的改进（同样的 30 对，6 个画像 × 5 对）

| 版本 | 做法 | 两次一致（调换红蓝顺序） |
| --- | --- | --- |
| 第 1 版 | A/B 命名，只给逐日文字（7B） | 16/30 |
| 第 2 版 | 红/蓝命名，并排数字表，先说最在意哪一项（7B） | 22/30 |
| 第 3 版，7B | 早晚课按个人时段算；主项几乎一样时由程序判 | 27/30 |
| **第 3 版，14B（定稿）** | 同上 | **28/30** |
| 第 3 版提示变体，7B / 14B | 主项几乎一样时告诉模型，让它看其他项 | 24/30 / 26/30 |

「主项几乎一样」指差距小于 0.25 天/周、0.5 小时空等/周、30 分钟早晚课/周。这时程序判断：一份在到校天数、空等、早晚课、最长的一天、只为一节课到校这 5 项上都不差，并且至少一项明显更好，就判它赢（支配关系）；否则判平局。
第 2 版里翻转的 8 对，原因是两份本来就差不多（模型从不答「差不多」），或者早晚课用固定的 9 点到 18 点算，和家长、夜猫子在意的时段对不上。第 3 版两点都改了。

### 正式标签（`labels_v3d_qwen2.5_14b.jsonl`）

- 80 个画像共 1,512 对。训练画像每人最多 16 对（主项明显不同的优先），测试画像每人 8 份候选两两全比（28 对），这样每个测试画像都有老师的前 3 名。
- 程序判 373 对（平局 174，支配 199），问 14B 的 1,139 对，每对按红蓝两种顺序各问一次。
- 问 14B 的对里两次一致 **89.3%**；算上程序判的，可用标签 1,390/1,512 = 91.9%。不一致的（翻转）不用。
- 位置偏向很小：先出现的「红」被选 1,211 次，「蓝」1,067 次。
- **局限**：14B 说出的「最在意哪一项」只有 72% 和画像标注的主项一致（7B 是 100%）。它常按句子里的其他说法挑项，比如「讨厌一天上很多课」它会挑「最长的一天」。所以老师并不总是按我们标注的主项来判。
- 用时：每对平均 4.5 秒，共约 90 分钟（Windows RTX 4090 笔记本，单路）。

## 4. Claude 核对（AI 核对者，不是真人）

总控窗口的 Claude 看到和千问完全一样的内容（句子、数字表、每周固定的课），红蓝顺序随机，没看千问的答案。判法写在 `check_answers_claude_method.md`：先按学生自己说的在意项依次比；在意项都打平时，只有一份各项都不差才选它，否则答「差不多」。

**150 对审核题**（从正式标签里随机抽，用来衡量标签质量）：

| 来源 | 和 Claude 一致 |
| --- | --- |
| 问 14B 的 123 对 | 109/123 = **88.6%** |
| 程序按支配规则判的 27 对 | 27/27（Claude 判卷也用支配规则，这个数有一部分是同一条规则自然得到的） |
| 合计 | 136/150 = 90.7% |

不一致的 14 对已换成 Claude 的答案（`labels_v3d_qwen2.5_14b_corrected.jsonl`），再训练。替换前后在同一份测试标签上比较（`cmp_uncorrected_on_corrected.json`）：逻辑回归 + 交叉项 89.2% → 90.5%，不看顺序的版本 88.7% → 88.7%，随机森林 92.4% → 91.2%，神经网络 92.6% → 91.6%。有升有降，都在误差范围内：14 个标签只占训练集的 0.6%，替换没有实际影响。

**60 对测试核对题**（来自 20 个测试画像，从没进过训练，也没用来调参）：

| 比较 | 一致（双方都选了一边的对） |
| --- | --- |
| 老师（14B + 程序规则）vs Claude | 39/42 = **92.9%**；其中问 14B 的对 29/32 = 90.6% |
| 最终模型 vs Claude | 45/50 = **90.0%**；主项明显不同 32/36，主项打平 13/14 |
| 最终模型 vs 老师 | 38/44 = 86.4% |

主项打平、程序判平局的 12 对，Claude 有 8 对也答「差不多」。

## 5. 模型对比（20 个测试画像，380 对有明确答案的标签）

训练用修正后的标签：836 对老师标签（14B 或程序判），再加 1,351 对免费的程序判对（合计 2,187 对）（训练画像候选里主项打平、且赢的一方在主项上也不差的对，不问模型）。补多少、超参数取多少，都只用训练画像上按画像分组的 5 折交叉验证来选，指标是「14B 判的对」和「程序判的对」两类准确率的平均。

| 方法 | 单对准确率（95% 区间） | 14B 判的 207 对 | 程序判的 173 对 | 前 3 命中（上限 0.91） | 老师第一名进前 3 | 每个学生耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 随机 | 50% | | | 0.375 | | |
| 等权打分 | 76.3%（68.3–83.4） | 65.7% | 89.0% | 0.66 | 0.78 | <0.1 毫秒 |
| 按 cares 打分（原占位版） | 68.6%（60.8–75.7） | 85.5% | 48.3% | 0.36 | 0.33 | <0.1 毫秒 |
| 逻辑回归，只用课表特征 | 76.1%（67.2–84.3） | 56.5% | 99.4% | 0.60 | 0.86 | <0.1 毫秒 |
| **逻辑回归 + 学生交叉项（已接进 rank()）** | **90.5%（84.0–95.8）** | **87.0%** | 94.8% | **0.80** | **0.93** | <0.1 毫秒 |
| 逻辑回归 + 交叉项，不看 cares 顺序 | 88.7%（81.9–94.7） | 86.5% | 91.3% | 0.80 | 0.93 | <0.1 毫秒 |
| 随机森林 | 91.2%（84.0–97.0） | 83.8% | 100% | 0.74 | 0.78 | 16 毫秒 |
| 小型神经网络（16 个隐藏单元） | 91.6%（85.7–96.8） | 85.0% | 99.4% | 0.83 | 0.88 | 0.7 毫秒 |
| 千问 7B 直接判断，每对问一次 | 75.5% | 82.6% | 67.1% | — | — | 每次 1.8 秒 |
| 千问 7B 直接从 8 份里挑前 3 | — | — | — | 0.41 | 0.51 | 每次 1.8 秒 |
| 千问 14B 直接从 8 份里挑前 3 | — | — | — | 0.54 | 0.81 | 每次 2.7 秒 |

怎么读这张表：
- 「前 3 命中」是模型的前 3 名和老师前 3 名的重合比例。老师的排名来自 8 份候选两两全比的胜场数，有并列时按份额算，所以就算完全猜中老师，平均也只有 0.91。
- 原占位版只看学生在意的那一项。主项打平时（173 对）它等于瞎猜，前 3 命中甚至低于随机。
- 学到的模型同时学会了「先看主项」和「主项打平时看其他项」，各项都明显好于两个规则基准。
- 三种学习模型的准确率差距在误差范围内。随机森林、神经网络在程序判的对上更准，但在 14B 判的对上不如逻辑回归。最后选逻辑回归：权重存成 4 KB 的 JSON，纯 Python 就能算，每份课表的得分还能拆成「每一项占多少」，方便解释推荐理由。
- 千问直接排序又慢又不如训练出的模型。7B 每对 1.8 秒，20 份候选两两比要 190 次，约 6 分钟。让它一次挑前 3，命中率和随机差不多。
- **cares 顺序有没有用**：交叉验证里两版打平（0.938 对 0.939）；在测试画像中在意两项的学生上，看顺序的版本准一些（87.2% 对 81.4%，86 对），但样本少，只能说「可能有一点用」。

学到的个人权重（每份课表的得分 = 各项乘权重相加，负数表示越少越好）：
- 通勤生（在意到校天数）：到校天数 −12.1，空等 −4.1，只为一节课到校 −3.4。
- 住得近（在意空等）：空等 −2.7，早课 −2.2，最长的一天 −1.5。
- 夜猫子（10:00–21:00，在意早晚课）：早晚课 −7.3，晚课 −5.6，空等 −4.9。

## 局限

- 画像、标签、核对都是 AI 产出，没有真实学生验证。模型学到的是「14B 扮演的学生」加上程序规则的偏好。
- 测试只有 20 个画像，区间较宽；三种学习模型之间的差距不显著。
- 14B 说出的主项只有 72% 和标注一致，老师本身有噪声；审核里 14B 和 Claude 的一致率是 88.6%。
- 支配规则同时用在打标签和 Claude 判卷里，所以程序判的对上的一致率偏高，不能当作独立证据。
- 线性的打分没法完全表达「先过阈值、再看其他项」这种规则，所以在主项明显不同的对上，模型偶尔会为了少来一天而接受稍多的空等。

## 6. 运行时

`rank()` 只用标准库：从候选的上课明细算 13 项特征，再用 `model.json` 里的权重算分。对 20 份真实候选算一次平均 3.6 毫秒（网页一次推荐有 7 个菜单，约 25 毫秒）。没有 `model.json` 时退回原来的规则打分。

## 复现

```bash
python3 -m llm.rank.personas                                   # 画像和划分
python3 -m llm.gpu_lock -- python3 -m llm.rank.label pilot --model qwen2.5:14b
python3 -m llm.gpu_lock -- python3 -m llm.rank.label run --model qwen2.5:14b
python3 -m llm.rank.check audit --labels llm/rank/output/labels_v3d_qwen2.5_14b.jsonl   # 150 对审核题
python3 -m llm.rank.check corrected --labels llm/rank/output/labels_v3d_qwen2.5_14b.jsonl
python3 -m llm.gpu_lock -- python3 -m llm.rank.direct --model qwen2.5:7b --labels llm/rank/output/labels_v3d_qwen2.5_14b_corrected.jsonl
python3 -m llm.gpu_lock -- python3 -m llm.rank.direct --model qwen2.5:14b --kinds listwise --labels llm/rank/output/labels_v3d_qwen2.5_14b_corrected.jsonl
/usr/local/bin/python3 -m llm.rank.train --labels llm/rank/output/labels_v3d_qwen2.5_14b_corrected.jsonl \
    --program-pairs strict --direct llm/rank/output/direct_qwen2.5_7b.jsonl llm/rank/output/direct_qwen2.5_14b.jsonl
python3 -m llm.rank.check score --labels llm/rank/output/labels_v3d_qwen2.5_14b_corrected.jsonl
```
随机种子固定（画像划分 2112，候选和配对 2112，核对题 check-2112）。
